# 赛博药箱 2.8.5：原生 Android 客户端（`android-v2/`）

`android-v2/` 是**赛博药箱**的主力原生 Android 客户端（当前版本 **`2.8.5` / `versionCode = 20805`**），基于 **Kotlin + Jetpack Compose** 构建，不嵌入 WebView 浏览器，也不下载网页端静态资源。客户端直接通过 `/api/*` JSON 与 SSE 接口与 Cloudflare Worker 后端通信；手机运行 AI 循环时，经 Worker 代理访问模型与 Tavily，只对公开网页执行无密钥直连。

---

## 兼容与迁移说明

- **独立包名与登录态**：客户端使用应用 ID `com.homemeds.app.v2`（早期 1.0 WebView 工程已从仓库移除）。
- **本地日历账号自动迁移**：自 2.1.0 起，客户端使用独立的本机日历账号「**赛博药箱**」（`CalendarContract.ACCOUNT_TYPE_LOCAL`）。每次执行日历同步或退出登录时，会自动清理早期 1.0 遗留的本机「家药箱」日历账号（仅清理 `ACCOUNT_TYPE_LOCAL` 类型的同名本地账号，绝不触碰系统其他日历或云端同步账号）。
- **网页端职责调整**：网页版已调整为纯管理员设置中心，家庭成员的日常服药、入库、计划、AI 助手及管理员全局使用日志均在本原生客户端中操作。

## 环境要求与编译构建

### 环境要求
- **JDK 21**
- **Android SDK Platform 37**（`compileSdk = 37`，`targetSdk = 36`，`minSdk = 29` 即 Android 10+）
- 首次构建需联网从 Google Maven / Maven Central 下载 Jetpack Compose、CameraX、Google ML Kit Barcode Scanning（随 APK 打包离线模型）、ZXing、OkHttp、WorkManager 及 Robolectric 测试依赖。

### 1. 配置本地 SDK 路径与服务端地址

在 `android-v2/local.properties`（已被版本库忽略，切勿提交）中指定本机 Android SDK 路径与线上服务端 HTTPS 根地址：

```properties
sdk.dir=/path/to/your/Android/Sdk
homeMedsBaseUrl=https://your-domain.example.com
# Windows 示例：
# sdk.dir=C\:\\Users\\<你的用户名>\\AppData\\Local\\Android\\Sdk
```

### 2. 运行单元测试、Lint 检查与构建 APK

```powershell
cd android-v2
# 如系统默认 JAVA_HOME 不是 JDK 21，请先指定：
# $env:JAVA_HOME = '<JDK 21 安装路径>'
.\gradlew.bat testDebugUnitTest lintQa assembleTest
# 正式版（开启 R8 代码压缩、优化与混淆，以及资源压缩）：
.\gradlew.bat lintRelease assembleRelease
# assembleRelease 自动执行 verifyReleaseScanner，校验压缩后 ML Kit 注册组件构造函数。
# 可选：仅支持 ARM64 设备的更小安装包，默认仍构建兼容四种 ABI 的通用包：
.\gradlew.bat assembleRelease -PhomeMedsAbis=arm64-v8a
```

- **测试产物**：`android-v2/app/build/outputs/apk/qa/赛博药箱测试-2.8.5-test.<N>.apk`。`assembleTest` 是 `assembleQa` 的别名（Android 保留 `test` 构建类型前缀）。沿用正式版的 R8 与资源压缩，独立验证测试版扫码注册组件。包名 `com.homemeds.app.v2.test`、桌面名称「赛博药箱测试」，可与正式版同时安装；FileProvider 与本地日历也独立。服务端数据仍取决于账号与地址，建议使用测试账号或通过 `-PhomeMedsBaseUrl=https://...` 指定测试服务端。
- **测试序号**：基于当前正式版自动生成 `<正式版>-test.<N>`，`versionCode` 保持正式版值。按基准版在已忽略的 `.gradle/test-builds/` 中保存已分配序号，每次测试构建递增，`clean` 不重置。失败构建也可能消耗序号。不要删除计数文件；可用 `-PhomeMedsTestBuild=N` 指定更高序号。只运行 Debug 单元测试或正式构建不消耗测试序号。
- **正式产物**：`android-v2/app/build/outputs/apk/release/赛博药箱-2.8.5.apk`。已配置从仓库根目录的 `.secrets/home-meds_android-release/` 读取正式签名材料，缺失时保持未签名，绝不回退到调试密钥。测试版优先使用同一正式签名，缺失时仅测试版回退到调试签名；切换签名后不能直接覆盖原测试版。切勿提交签名材料或输出密码。保存 `app/build/outputs/mapping/release/mapping.txt` 以便还原混淆堆栈。
- **按设备架构精简**：`-PhomeMedsAbis=arm64-v8a` 生成 `赛博药箱-2.8.5-arm64-v8a.apk`；也支持逗号分隔的 `arm64-v8a,armeabi-v7a,x86,x86_64` 子集。此参数只裁剪本地库，不移除离线扫码模型；仅在明确设备 ABI 时使用，不能将 ARM64 专用包分发给 32 位设备或 x86 模拟器。体积对比见 [`docs/optimization.md`](../docs/optimization.md)。
- **地址优先级**：命令行 `-PhomeMedsBaseUrl=https://...` > `android-v2/local.properties` 中的 `homeMedsBaseUrl` > 仓库默认占位符 `https://your-domain.example.com`。正式客户端仅支持 HTTPS，不支持明文 HTTP。

## 核心界面与业务能力

### 分组码注册与扫码

在「注册成员」中先输入家庭分组码，或点击「扫描分组码二维码」扫描管理台「家庭设置」中显示的二维码，再填写用户名并确认注册。分组码为空时不能填写用户名或提交注册，服务端以注册写入时仍有效的分组码决定所属家庭；错误或已更换的码不能创建账号。

扫码只填写分组码，不自动注册、不打开网址、不更改服务器地址。仅接受 `home-meds.join` 第 1 版二维码；普通网址、药品码或多个不同邀请不会被自动选用。关闭扫码或拒绝相机权限后可继续手动输入，原先填写的资料不丢失。二维码只包含格式版本和分组码，不包含真实域名或 API 地址。

### 1. 今日清单与两步服药核对
- 顶部一行显示日期与「扫码查药 / 入库」入口；过期/30 天临期药盒以单行提示条显示，点按查看具体药盒；家人进度以「姓名 已记录/总数」筛选标签切换。
- 每条待办显示时间与状态标签、药名 · 用量 · 餐时，主按钮「核对并记录服药」旁的「⋮」菜单提供「这次跳过」与「朗读」；已记录项显示记录人与「撤销」。刷新今日清单使用顶栏刷新图标。
- **两步服药确认**：
  - 自动按「计划指定的优先药盒 → 上次使用的可用药盒 → 已开封且到期早的药盒」预选；若优先药盒已用尽或报废，不会静默改扣其他药盒，强制要求用户手动重选。
  - 支持扫描药盒 20 位追溯码精确匹配具体药盒（普通商品条码因无法区分批次，仍需手选药盒）。
  - 必须勾选「已核对实物药名、规格、有效期、批号及用量」方可提交；若所选药盒已过期，还需额外勾选过期二次确认。
  - 提交时携带药盒 `expected_stock_version` 乐观锁，支持记录服药、跳过本次及当日撤销（原子恢复库存）。

### 2. 药箱库存、药品资料与出入库向导
- 分段标签查看「在库药盒」、「药品资料」与「库存流水」；点按药品资料卡片查看通用名、适应症、注意事项与来源。
- **在库药盒筛选与排序**：搜索框可匹配药名、批号、药箱名与追溯码；下方快捷标签可按状态（在库/用尽/报废/全部）、药箱筛选，并切换排序（有效期从早到晚/从晚到早、药名、余量从少到多/从多到少、最近入库、按药箱分组）。「更多筛选」对话框还可按药品、有效期（已过期、30 天内到期、未过期、未填写）和开封状态筛选。未填写有效期的药盒在两种有效期排序下都排在最后；余量为 0 的在库药盒按「用尽」筛选。列表上方显示「显示 N / 总数 盒」及当前条件，可一键「恢复默认」。筛选与排序按家庭保存在本机，已删除的药箱或药品条件会自动视为「全部」。
- 药盒卡片「⋮」菜单提供用掉、移到另一药箱与报废；管理员卡片上直接显示「修改药盒资料」。入库向导按钮按行排列，AI 检索收在可展开区域。
- 管理员可直接编辑共用药品资料与条码前缀映射，或通过带 `expected_version` 乐观锁的表单修改具体药盒的有效期、批号、序列号、追溯码、每盒装量与开封状态。

### 3. 服药计划管理
- 支持每天、每周固定日、每隔 N 天、按需四类计划，提供早/中/晚餐时快捷标签、关联药品并记住一盒「优先药盒」、暂停/恢复与编辑删除。
- 计划页顶部提供「新建吃药计划」与成员筛选标签；计划卡片显示一行摘要，「暂停计划」位于「⋮」菜单。编辑器成对排列用量/单位、频率/餐时、开始/结束日期，备注、优先药盒与两个开关收在「更多选项」。

### 4. 设置中心与管理员能力
- 设置页是一个短菜单，每一行打开带返回箭头的子页面（导航路由 `settings/*`）。
- **关于软件**：所有成员均可查看当前 APK 的版本名称与版本号、离线 MIT 许可证全文和版权声明，并点击 GitHub 项目主页跳转浏览器。
- **方向变化保留进度**：主 Activity 直接处理方向与窗口尺寸变化，Compose 随新尺寸重新布局，不因横竖屏切换销毁页面或取消页面任务。表单、两步确认、照片、弹窗和进行中的查询保留在内存中；这不承诺系统杀死进程或其他类型 Activity 重建后的草稿恢复，也不将密码、照片或医疗草稿写入实例状态。
- **所有成员可见**：助手偏好（计划对象选择、是否开启「手机运行 AI 循环」）、日历与提醒（同步哪些家人的计划、日历响铃与应用通知开关、上次同步与「立即同步」）、权限与后台（日历、通知、精确闹钟、电池优化各一行，显示状态与「去开启」）、账号与安全（账号、验证器与恢复码状态、「重新生成恢复码」对话框、退出登录）。
- **管理员专属**：
  - 账号安全：TOTP 验证器本地二维码生成与唤起、一次性恢复码生成（在对话框中输入 6 位验证码）与保存为本地文件。
  - 家庭管理：顶栏家庭切换下拉、创建家庭、设置三餐时间、成员移组与老人模式开关、药箱新增/改名/删除（列表行的「⋮」菜单）、在选择对话框中重置其他管理员验证方式。
  - AI 配置：摘要卡片与「编辑完整 AI 配置」，「⋮」菜单提供读取模型、检测内置检索、保存、能力探针与测试药品查询（对话框）；提供商（DeepSeek 官方 / 其他 OpenAI 兼容接口）、搜索来源（内置搜索 / 外部 Tavily / DuckDuckGo）、每日配额与超时。
  - **使用日志**：跨家庭查看操作审计、AI 查询明细、AI 用量、服药记录与库存流水五类日志，筛选条件收在「筛选」对话框，支持按用户、家庭、日期、成功/失败状态与操作类型筛选及游标分页。

### 5. 老人模式与无障碍
- 底部导航固定为「**今日、药箱、助手、计划、设置**」（助手居中）。开启老人模式后自动隐藏「助手」与「计划」标签，仅保留核心服药、药箱与设置入口。
- 普通模式最小触控尺寸 `48dp`；老人模式最小触控尺寸 `60dp`、正文字号 `22sp`。选中标签页使用浅绿底深色字（`#DCEBD4` / `Ink`），主按钮与危险按钮均满足 WCAG AA `4.5:1` 对比度要求。

## 图片识药与统一 AI Agent Loop

### 1. 「赛博药箱AI助手」交互体验
- **Markdown 回复**：完成的助手消息与流式回复使用原生 Compose 渲染 CommonMark，支持加粗、斜体、标题、有序/无序及嵌套列表、引用、代码块、删除线、链接与 GFM 表格；宽表格和代码块可横向滚动。用户原文不作格式转换。仅公开 HTTP/HTTPS 链接可点击，HTML 按文字显示，不执行脚本或自动加载远程图片。
- **固定底栏与独立滚动**：页面标题固定为「赛博药箱AI助手」，右侧提供带二次确认的「清空」按钮（清空后立即取消进行中的流式请求，清除当前会话上下文、推荐回复、输入框、图片附件与未保存草稿，不影响已入库数据；正在保存正式数据时禁用清空）。消息历史与待确认草稿独立滚动，底部输入区始终固定可见。
- **旋转与页面重建**：对话历史、流式回复、输入框、已选图片、推荐回复与待确认草稿由 Activity 的 `AppViewModel` 在内存中持有，横竖屏切换或切换底部页面不会中断请求或清空会话。明确清空、退出登录、切换账号/家庭/计划对象/运行方式时取消并清除旧会话，旧请求的延迟结果不能恢复已清空内容。聊天不写入磁盘或 `savedInstanceState`；结束应用或系统杀死进程后不恢复会话。
- **输入区集成动作**：输入区左下角为拍照/选图按钮，右下角为中文语音输入与发送按钮；模型流式回复期间发送按钮自动切换为停止按钮。
- **中文语音兼容**：语音输入优先使用系统识别弹窗；无弹窗或启动受限时，申请录音权限并回退到 `SpeechRecognizer` 服务。识别文本追加到当前输入末尾（最多 6000 字符），不自动发送；后台听写支持取消，离开页面或超时会释放麦克风。朗读依次尝试多个中文 Locale，初始化失败、超时或提交朗读失败时重新绑定引擎并重试一次。手机仍需安装并启用中文语音引擎，MIUI 可在系统「文字转语音输出」中选择小爱语音引擎。
- **模型动态推荐回复（`<suggested_replies>`）**：输入区上方展示由模型根据当前对话动态生成的最多 3 条简短后续回复建议（流式边界过滤器 `ReplySuggestions` 自动剥离元数据标签，确保标签绝不泄露到可见正文中）。点击建议仅填入输入框，由用户核对后手动发送。
- **助手偏好持久化**：在「设置 → 助手偏好」中按「登录账号 + 家庭」持久化保存当前对话的「计划对象」与「手机运行 AI 循环」开关。切换计划对象、家庭或连接方式会自动开启新会话，防止跨家庭或跨成员混用草稿。

### 2. 多角度拍照组件与本机图片预处理
- **三处入口共用**：首页「扫码查药 / 入库 → 拍照查药 / 入库（多角度）」、AI 助手输入栏左下角拍照按钮，以及入库向导第二步 / 管理员「修改药盒资料」中的「拍照识别有效期 / 批号」共用同一套多图选择弹窗。
- **最多 6 张多角度采集**：支持分次调用系统相机拍摄同一药盒的正面、背面、侧面、盒底或说明书，或从系统相册一次多选，合计最多 6 张。弹窗内照片网格独立滚动，支持逐张移除与补拍；点击右下角带数量角标的对勾按钮前仅暂存在本机，不会每拍一张就调用一次 AI。
- **私有缓存隔离与权限降级**：系统相机通过私有 `FileProvider`（仅暴露 `cache/medicine-camera/` 下的当前临时文件）获取一次性读写授权，拍摄完成、取消或异常后立即回收授权并删除临时原图。若拒绝相机权限或设备无相机应用，仍可正常使用相册选图。
- **本机重编码与隐私脱敏（`PhotoEncoder`）**：
  1. 相册原图文件大小上限为 `25 MiB`。
  2. 先读取并完整应用全部 8 种 EXIF 旋转与镜像方向，确保传给视觉模型的文字方向正立。
  3. 按最长边不超过 `1280px` 等比缩放，以 JPEG 质量 `82` 重编码；若单张体积仍超过 `400 KiB`，继续降质/等比缩小直至不超限。
  4. 重编码过程彻底剥离原始 EXIF 元数据（如 GPS 位置、拍摄设备信息）。
  5. 界面预览仅保留最长边不超过 `320px` 的小尺寸缩略图，6 张满载时总位图内存占用严格受控。

### 3. 多图合并识药、特写日期识别与有效期规则
- **多角度合并识别**：同一药盒的多张照片在同一条多模态消息中一并发送给视觉模型，综合提取药名、通用名、规格、厂家、批准文号/条码、每盒数量、有效期与批号；若不同照片间存在信息冲突或看不清则留空，绝不猜测，也不为每张照片单独建盒。
- **有效期与批号特写识别**：在入库第二步或药盒资料编辑页可单独拍盒底/钢印特写识别有效期与批号，不要求特写画面中出现药名。严格只抄录包装上明确印刷的「有效期至 / 失效日期 / EXP」，禁止将生产日期当作有效期，也禁止根据保质期月数自行推算。识别期间禁用保存按钮；取消识别或未能识别清楚时保留表单原有值。
- **年月精度有效期（`MedicineExpiry`）**：支持完整日期（如 `2028-06-09`、`2028.6.9`、`2028年6月9日`、`20280609`）与仅年月（如 `2028-06`、`2028.06`、`2028年6月`、`202806` 及全角数字）。AI 草稿与输入框保留 `YYYY-MM` 年月显示，并在表单下方明确提示「包装仅标年月，确认保存时按月末 `YYYY-MM-DD` 记录。请核对实物」（自动按实际大小月与闰年计算月末日，如 `2028-02` 展开为 `2028-02-29`，`2027-02` 展开为 `2027-02-28`）；不合法或含糊文本（如仅年份、`2028-13`、`有效期24个月`）直接报错拒绝。
- **扫码追溯码精确优先**：同画面出现商品条码与 20 位追溯码时优先采用追溯码；若同画面出现多个不同药盒的追溯码则拒绝自动任选。扫描已入库追溯码时，直接定位具体药盒及所属药品（即使该药品尚未建立条码前缀映射，或药盒处于已用完/已报废状态），展示该盒详情并禁用重复入库。

### 4. 统一 AI Agent Loop 与待确认双草稿卡片
- **统一多轮工具循环**：在 `AiAgent.kt` 中以统一循环处理模型推理与工具调用。查询家庭药品/成员/计划的工具（`find_medicines`、`list_medicines`、`get_member_plans`、`request_plan_details`、`add_plan_draft`、`propose_plan_update`、`propose_plan_pause`）回调服务端 `/api/app/ai/tool` 执行（每轮最多 5 次）；手机端本地公开检索（`search_web`）、网页正文抓取（`fetch_page`）与药品入库草稿生成（`propose_medicine_draft`）使用独立配额计数。
- **草稿强制人工确认**：
  - **药品草稿卡片**：展示识别出的药名、规格、厂家、每盒数量、有效期、批号与条码，点击「打开核对并入库」才进入入库向导。仅当本地药品库存在唯一匹配的「药名 + 规格 + 厂家」（或已入库追溯码精确命中）时才自动关联已有药品；否则引导用户先核对新建药品资料，再核对药盒批次入库。
  - **计划草稿卡片**：展示新增、修改或暂停服药计划的完整参数，点击「打开核对并保存」进入计划确认弹窗（可选择优先药盒）。**AI 从不直接写库**。

## 本地日历与精确闹钟提醒

1. **防抖与周期同步**：应用启动时注册通知渠道与 6 小时一次的 `WorkManager` 周期任务；登录、切换家庭、增删改服药计划、记录服药或调整提醒设置时，触发 `1.5 秒` 防抖同步。前台已通过聚合接口取得的最新计划快照会直接用于重建本地日历与闹钟，避免重复发起网络请求；后台周期任务则调用轻量接口 `GET /api/app/sync`。
2. **本地日历写入**：在系统日历中维护本机私有账号「赛博药箱」，根据所选家庭成员的启用计划、家庭时区（`ZoneId`）与 `RRULE` 写入 15 分钟时长的重复事件，事件描述明确标注「提醒不代表已经服药」。
3. **48 小时闹钟与响铃前核对**：
   - 使用 `AlarmManager` 预先编排未来 48 小时内的提醒：本人计划按设定时间触发；所选家人的计划若开启「通知家人」，在计划时间延后 30 分钟触发（老人模式账号不接收家人超时提醒）。
   - 闹钟到点唤醒后，先向服务端实时请求该家庭今日清单核对：若该次服药已记录、已跳过，或计划已修改/暂停，则静默结束不发通知；若离线无法联网核对，仍发出通知并在文案中注明尚未联网核对。
   - 点击通知直接进入客户端对应家庭的服药核对弹窗，不会在后台自动勾选服药。

## 网络聚合与安全架构

- **聚合接口与平滑回退**：
  - 冷启动与手动刷新调用 `GET /api/app/bootstrap?group_id=...`，一次请求获取当前用户、可选家庭、成员、共用药品、在库药盒、服药计划、药箱列表与今日清单。
  - 家庭内写操作（如记录服药、入库、修改计划）携带请求头 `X-HomeMeds-State: app` 与 `X-HomeMeds-Client: android`，直接消费响应中的 `app_state` 更新界面与本地提醒；若服务端返回 `state_error`（快照生成失败或超限），仅补发一次读取刷新，**绝不重复提交已成功的写操作**。
  - 若连接的旧版服务端对 `/api/app/bootstrap` 返回 `404/405/501`，客户端自动降级为分项并发读取并在后续写操作中省略 `X-HomeMeds-State`。
- **会话与防截屏安全**：
  - 会话 Cookie 保存在应用私有 `SharedPreferences` 中，不使用系统 WebView `CookieManager`。所有写请求自动注入同源 `Origin`，家庭请求注入 `X-Group-Id`。
  - `AndroidManifest.xml` 禁用系统自动备份（`allowBackup="false"`），并在管理员绑定、恢复码展示、TOTP 二维码与 AI 密钥配置等敏感状态开启窗口 `FLAG_SECURE` 阻止截屏与录屏。
- **Worker 代理与无密钥网页抓取**：
  - 手机通过 `/api/app/ai/session` 申请无公钥会话，模型与 Tavily 请求通过 `/api/app/ai/provider` 转发。模型与搜索密钥只由 Worker 持有，客户端不生成设备 RSA 密钥、不解封提供商凭据。
  - 服务器绑定用户/家庭、会话期限与次数，强制路径白名单、模型及 token 上限。手机保留 agent 循环、SSE 解析、6 张照片识别、只读远程工具与本地草稿。
  - `NativeHttp` 只抓取无密钥的公开网页，使用 `Proxy.NO_PROXY`、逐跳公网 URL/DNS 检查与响应体上限，避免系统代理绕过目标 DNS 检查。
  - TOTP 剪贴板标记为敏感，60 秒后仅清除本次复制的内容；`otpauth` 通过系统选择器打开。语音弹窗使用隐式 Intent，识别服务仅选择系统配置或默认实现。所有动态 API ID 路径段先校验 `^[A-Za-z0-9_-]{1,100}$` 再编码。

## 版本策略（Semantic Versioning 2.0.0）与变更历史

客户端严格遵循 **Semantic Versioning 2.0.0**，版本号计算公式为：

```text
versionCode = MAJOR * 10000 + MINOR * 100 + PATCH
```

（为避免 `versionCode` 编码碰撞，`MINOR` 与 `PATCH` 均须小于 `100`。）
- **MAJOR（如 `3.0.0 / 30000`）**：不兼容的 API、本地数据格式或核心交互契约变更。
- **MINOR（如 `2.4.0 / 20400`）**：向后兼容的新功能或内部架构增强。
- **PATCH（如 `2.4.1 / 20401`）**：向后兼容的缺陷修复。
- *注：Cloudflare Worker 与 Pages 管理台独立按主干持续部署，不沿用 APK 版本号。*

## 2.7.0 安全升级与运维要求

提供商长期密钥只在 Worker 中解密、注入，不再下发给 Android。手机保留 agent 循环、多图识别、网页读取和本地草稿工具，通过 `POST /api/app/ai/provider` 代理模型与 Tavily 请求。会话绑定当前用户及家庭，有效期 15 分钟；每会话模型最多 12 次、搜索最多 5 次，路径白名单、模型、输出 token 上限、超时及禁止跟随重定向均由 Worker 强制执行。聊天中的公开检索单独申请 lookup 会话，不能借聊天会话绕过检索配额。只有代理路由使用 4 MiB 请求体上限，其余 API 保持 256 KiB。

旧版 APK 携带 `public_key` 申请会话时收到 `501`，文字查药/对话自动回退到 Worker `/ai/lookup`、`/ai/chat`；旧版照片识别不再可用，需升级到 2.7.0。新版不上传设备公钥，也不接收加密凭据。

迁移 `0008_security_fixes.sql` 增加代理调用计数、Push 重试次数及订阅失败计数，并清空来源不可信的共享药品缓存。只有管理员保存的 confirmed 药品可写共享缓存，读写均仅保留 `name, generic_name, manufacturer, specification, indications, precautions, base_unit, units_per_package, sources`，不含追溯码、状态、批号或有效期。

Push 订阅每用户每小时限 10 次，最多保留最新 5 个。首次发送失败后最多重试 3 次，间隔 5/10/20 分钟；订阅成功后失败计数清零，连续失败 10 次删除，404/410 立即清理。每轮 Cron 全局最多 150 条、每家庭最多 30 条，并发 6、单次超时 5 秒；未领取任务留待下一轮。

**部署后必须在管理台轮换 LLM 和 Tavily 密钥，并在提供商侧撤销旧密钥。历史下发的长期密钥应视为已泄露，15 分钟会话期限从未使其失效。** 轮换提供商密钥，不要替换 `APP_ENC_KEY`。先应用迁移再发布新 Worker，迁移到发布之间旧 Worker 仍可能重新写入共享缓存，应缩短窗口并在切换后确认清理。这里仅说明发布要求，本次修复不执行部署、远程迁移或密钥轮换。
