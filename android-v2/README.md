# 赛博药箱 2.4.0：原生 Android

独立 Jetpack Compose 客户端，不嵌入浏览器、不下载赛博药箱网页资源。仅访问现有服务端 `/api/*` JSON / SSE；手机端 AI 可直接访问后台配置的模型、Tavily 和公开资料页。

`android/` 1.0 保持不变。2.x 使用应用 ID `com.homemeds.app.v2`，可与 1.0 并存，不继承其浏览器登录态，需要重新登录。2.1 起使用独立本地日历账号「赛博药箱」，同步和退出时会清理旧版遗留的「家药箱」本地账号（不会清理其他账号或远端日历）。如仍使用 1.0，请关闭其日历同步，避免旧账号被重新创建。应用 ID、偏好与服务端地址保持不变。

## 编译

需要 JDK 21、Android SDK 37。首次构建需联网下载 Compose、CameraX、ML Kit（随 APK 打包离线模型）、ZXing 等依赖。

在 `android-v2/local.properties` 配置本机 SDK 路径（不提交版本库），例如：

```properties
sdk.dir=C\:\\Users\\YOUR_USER\\AppData\\Local\\Android\\Sdk
```

```powershell
cd E:\Temp\Projects\home-meds\android-v2
$env:JAVA_HOME='C:\Program Files\Java\jdk-21'
.\gradlew.bat testDebugUnitTest lintDebug assembleDebug
```

产物：`app/build/outputs/apk/debug/赛博药箱-2.4.0-debug.apk`。默认服务器为 `https://home-meds.pages.dev`，可以通过 `-PhomeMedsBaseUrl=https://your-host.example` 更换 HTTPS 同源根地址。不支持明文 HTTP。

## 界面与能力

- 今日本人和家人清单、过期/临期提示、扫码查询和入库。
- 两步服药核对、实物确认、追溯码精确匹配、过期二次确认、`expected_stock_version` 乐观锁、跳过与撤销。
- 库存、药品资料、流水；管理员编辑药品/条码映射及 `expected_version` 药盒资料。
- 每日/每周/间隔/按需计划、餐时快捷键、优先药盒、暂停和编辑。
- AI 流式对话、中文语音输入/朗读、待确认新增/修改/暂停草稿。草稿不自动写入正式计划；支持图片附件和待确认药品入库草稿。
- 管理员 TOTP 本地二维码、验证器唤起、一次性恢复码文件保存和重生成；家庭切换、餐时、成员转组/老人模式、药箱管理、其他管理员凭据重置。
- AI 提供商、模型、搜索协议、配额/超时、接口探针与测试查询；五类全局日志、筛选和游标分页。
- 配色复用网页设计令牌。普通控件至少 48dp，老人模式至少 60dp、正文 22sp，隐藏计划和助手底部导航项。

## 提醒

应用启动建立通知渠道与 6 小时 WorkManager 周期任务。登录、切换家庭、计划/服药变更和提醒设置变更触发 1.5 秒防抖同步。

日历使用所选成员的家庭时区和 RRULE。应用闹钟覆盖未来 48 小时；本人按计划时间提醒，非老人用户可接收所选家人超过 30 分钟未记录的提醒。触发时核对当前计划与服药记录，无法联网时通知明确提示尚未核对。点击通知打开对应家庭的原生确认弹窗，过时或已记录的提醒不会直接重复记录。

请在「设置 → 提醒与账号」授权日历、通知和精确闹钟，并检查电池优化。拒绝精确闹钟时使用系统尽力调度，不能保证准点。离线、系统限制后台运行和设备关机都会影响提醒，不能作为唯一用药保障。

退出或换家庭会清理旧日历和闹钟。跨家庭只同步当前所选家庭。

## 网络与安全

- 初始化使用一次 `/api/app/bootstrap` 聚合家庭状态；家庭数据保存直接复用响应中的 `app_state`，不再逐项重读。服务端不支持聚合或家庭数据超过 2 MiB 时回退旧分项接口；认证/权限和其他服务错误不额外重试。快照失败只补刷新，不重复写入。
- 后台同步使用一次 `/api/app/sync` 返回计划和时区。前台已取得的新快照直接应用本地日历和闹钟，提醒设置变化优先重用同一家庭的计划缓存；到点核对仍访问服务器。
- Pages 网页已调整为管理员设置中心，普通家庭成员请使用本原生客户端；手机端日常操作与管理员日志入口保留。本轮 APK 版本为 `2.4.0 / 20400`。

- Cookie 存在应用私有偏好中，不使用 `CookieManager`。写请求附带同源 `Origin`，家庭请求附带 `X-Group-Id`；服务端仍负责鉴权。
- 禁用备份与敏感页面截屏。密钥、恢复码、二维码与聊天不写入应用日志。
- 手机 AI 通过 Android Keystore RSA-2048、RSA-OAEP-SHA1 + AES-256-GCM 接收临时凭据；不保证所有设备具备硬件后端，使用系统提供的 Keystore。
- 只向配置的 HTTPS 提供商根路径注入密钥，带凭据请求不跟随重定向；公开抓取验证 URL 和所有 DNS 答案，限制重定向、响应大小、超时与工具次数。
- 内置搜索支持 Responses、Chat Completions 和 Anthropic。外部搜索使用 Tavily，可选 DDG；来源须来自实际检索。AI 药品资料始终待人工核对。
- 未建立手机 AI 会话时可回退服务端 SSE；不会在手机端已经消费配额后静默重跑。可在「设置 → 助手偏好」关闭「手机直接连接模型」。
- 恢复码原文只能在生成时保存；现有 `/auth/recovery` 仅提供剩余数量，无法重新读取旧码。

## 验证范围

JVM 测试覆盖日程/夏令时/RRULE/48 小时闹钟、密钥解封和地址策略、GS1/GTIN/追溯码、选盒规则、Cookie/Origin/数组接口、SSE、取消请求和思考标签过滤。

还需在真机验收：相机实物码、中文语音引擎、系统日历提供商、通知权限/精确闹钟、重启恢复、各厂商后台限制，以及真实管理员/家庭的端到端流程。新增 JVM 回归覆盖多模态消息、容器字段、双类型草稿、搜索会话复用、独立工具额度、来源校验、取消清理与重复预填。Robolectric 验证图片编码、八种 EXIF 方向、六图批次资源上限及日历账号迁移；Compose 回归验证首页扫码/拍照分流、逐张移除、统一提交及查询后人工入库。JVM 与 Lint 不能代替这些真机验证。

## 版本策略（Semantic Versioning 2.0.0）

当前版本 **2.4.0**，`versionCode = 20400`，上一版为 `2.3.0 / 20300`。本次新增拍照识别药盒有效期 / 批号，有效期支持仅到月份（按当月末日判断）；已入库追溯码优先定位具体药盒。手机初始化、保存和提醒同步使用聚合接口并复用返回快照，减少重复请求；服务端保留旧接口与回退能力。现有 API、本地数据及人工确认机制保持兼容，按新增能力和内部架构增强使用 **MINOR** 递增。Pages 管理台独立部署，不沿用 APK 版本号。

`2.3.0 / 20300` 在 `2.2.0 / 20200` 基础上新增模型推荐回复与可持久化的助手偏好，将消息滚动区与固定底部输入区分离，集成拍照、语音和发送图标，由模型主动生成待确认草稿；拍照改为系统相机，照片弹窗使用独立滚动网格和带数量角标的对勾。保留扫码、多角度识药和人工确认保存能力。

`2.2.0 / 20200` 在 `2.1.0 / 20100` 基础上新增最多 6 张多角度照片合并识药、相册多选及首页直接拍照查询。

`2.1.0 / 20100` 在 `2.0.0 / 20000` 基础上新增统一 AI Agent Loop、图片识药与待确认药品草稿，并更名为赛博药箱。

编码规则：`MAJOR * 10000 + MINOR * 100 + PATCH`。为避免编码碰撞，此编码方案下 `MINOR`、`PATCH` 均须小于 100。

- **PATCH**，例如 `2.1.1 / 20101`：向后兼容的缺陷修复。
- **MINOR**，例如 `2.2.0 / 20200`：向后兼容的新功能或内部架构增强。
- **MAJOR**，例如 `3.0.0 / 30000`：不兼容的 API、数据格式或交互契约变更。

## 图片识药与统一 AI Agent Loop

- 助手页标题为「赛博药箱AI助手」。消息与待确认草稿独立滚动，底部输入区固定；拍照位于输入区左下角，语音与发送为右下角图标按钮。回复期间发送按钮替换为停止按钮。
- 底部导航依次为「今日、药箱、助手、计划、设置」，助手位于中间。老人模式仍隐藏助手和计划。
- 助手页右上角可清空对话历史，需二次确认；确认后停止当前回复并清除本次对话上下文、推荐回复、输入、图片附件及未保存草稿，不影响已保存的药品、库存或计划。取消操作保留原对话；正在保存正式数据时禁用清空按钮。
- 输入区顶部的可选回复由模型按当前对话生成，无固定快捷话术；点击只填入输入框，不自动发送。手机直连与服务端文字 SSE 均支持，推荐回复元数据不显示在消息正文；模型未提供或格式不正确时不显示推荐。
- 仅保留发送入口，模型在信息充分且用户表达记录意图时主动调用药品或计划草稿工具，缺少信息先追问。所有草稿仍需人工核对保存。
- 「计划对象」与「手机直接连接模型」移至「设置 → 助手偏好」，普通家庭成员也可设置。计划对象按登录账号及家庭保存，默认为家庭内的本人；对象已移出家庭或管理员不是家庭成员时，需在设置中明确选择，不会任意替换为他人。切换对象、家庭或连接方式会开始新的对话，避免沿用不匹配的草稿。
- 首页「扫码查药 / 入库」可选择「扫描条码 / 追溯码」或「拍照查药 / 入库（多角度）」。拍照查询先展示药品资料、有效期、批号与家庭库存匹配，点击「核对并入库」才打开原有入库向导，不会自动保存。
- 入库第二步和管理员「修改药盒资料」均可单独拍照识别有效期 / 批号，不要求特写中有药名；只能抄录同一药盒上可见的有效期至、失效日期或 EXP，不能把生产日期当有效期，也不能按保质期推算。识别期间禁用保存；识别不清或取消时保留原值，始终需要人工核对。
- 有效期支持完整日期和仅年月（如 `2028-06`、`2028.06`、`2028年6月`）。AI 草稿保留年月精度，不补猜日；表单明确提示仅年月在确认保存时按当月最后一天记录，闰年和大小月按实际日历计算。发送给现有服务端的仍是完整日期或空值，不改变存储协议。
- 扫码时优先追溯码而非同画面商品码，多个不同药盒的追溯码不会自动任选。已入库追溯码优先按具体药盒及当前家庭药品匹配，不依赖条码前缀映射；可查看该盒日期、批号和状态，包括用尽 / 报废的药盒，但仍禁止重复入库。服药核对仍要求药盒在当前计划的可用列表中，不会放宽扣库存规则。
- 首页、对话和药品入库共用多图拍照组件：同一药盒最多 6 张，可分次调用系统相机拍摄正面、背面、侧面、盒底或说明书，也可从相册多选。弹窗只展示已选照片，不嵌入相机预览；照片网格独立滚动，底部固定相机图标、相册图标和带数量角标的对勾按钮。支持逐张移除和补拍；点击对勾前只暂存在本机，不会逐拍调用 AI。对话中还需点击发送才提交图片。
- 系统相机通过私有 FileProvider 只获得当前临时照片的读写授权，拍照完成、取消或启动失败后清理临时照片与授权。应用本身因扫码功能声明了相机权限，拍照前仍会申请权限；拒绝权限、没有相机应用或拍照失败时可改从相册选图，已有照片保留。
- 多张照片在同一条多模态消息中发送，综合识别为同一药盒的资料，不是每张照片分别创建一盒。不同药品、不同药盒或不同批次须分开查询；识别冲突字段不得猜测，必须人工核对。原有文字和单图调用仍兼容。
- 图片先在本机纠正全部 EXIF 旋转/镜像方向，再按最长边不超过 1280px 缩放，以 JPEG 质量 82 压缩。若仍超过 400KiB，继续等比缩小；重编码会移除 EXIF 等元数据。相册原文件限制为 25MiB，临时文件处理后删除。每张界面缩略图最长边 320px，避免多张照片同时保留大位图；完整识别图仍保留上述 1280px 上限。
- 只向已配置的模型提供商发送图片，请避免拍入个人信息。含图请求即使关闭手机直连，也优先直连模型，绝不降级到只接受字符串消息的旧服务端 SSE。400/422 会提示切换支持视觉的模型，例如 qwen3.5。
- 统一循环处理多轮推理与工具调用。家庭药品、成员和计划工具仍调用现有 `/api/app/ai/tool`，每轮最多 5 次；本地搜索、网页读取和药品草稿有独立的配置额度，不占这 5 次。模型请求含内置搜索一起遵守配置的最多 3–6 轮限制。
- 对话按需开启并复用一个查药会话取得 Tavily 凭据；也可使用提供商内置搜索或已启用的 DuckDuckGo。所有已建立会话在成功、失败或取消时都会结束，不会把搜索密钥发给网页。
- 容器识别先用现有对话会话协议取得模型凭据，不强制要求配置搜索密钥。管理员使用当前家庭的成员建立会话，家庭无成员时需先添加成员。图片可仅按可见文字返回 `pending / requires_confirmation` 资料；看不清的字段留空。纯文字查药仍必须有本轮实际检索到的公开来源，模型编造的链接不采信。
- 对话的药品草稿显示规格、厂家、每盒数量、有效期、批号和条码，点击「打开核对并入库」后才进入人工确认。匹配已有药品时仅自动选择唯一的药名/规格/厂家匹配项；新药先核对创建资料，再核对有效期、批号、数量和存放药箱后入库。
- AI 从不直接保存药品、药盒或正式计划。药品和计划是独立的待确认卡片；新建药品刷新后，可在计划编辑器中选择关联。
